가격 추적기 v10 안내 — Toss Payments 결제 승인 연동
====================================================

v10은 v9의 사용자/상품/요금제 기능을 유지하면서 Toss Payments 단건 카드 결제 승인 흐름을 추가합니다.

추가된 기능
- 로그인 사용자용 PRO 30일 이용권 결제 버튼
- 서버에서 주문 생성 및 결제 금액 고정
- Toss Payments 결제 승인 API 서버 호출
- 결제사 응답의 DONE 상태, 주문번호, 총 결제금액 검증
- 동일 주문 중복 승인 요청 방지 및 결제 주문 이력 저장
- 결제 승인 후 PRO 30일 활성화 (기존 PRO 잔여기간이 있으면 그 뒤에 30일 연장)
- 관리자 수동 플랜 변경 기능은 기존대로 유지

가격
- 초기 예시 가격은 3,900원 / 30일 이용권입니다.
- .env의 PRO_PRICE_KRW로 변경할 수 있습니다.
- 이 결제 흐름은 30일 단건 이용권 구매입니다. 자동 카드 정기결제/자동 갱신은 아직 구현하지 않았습니다.

Toss 테스트 연결 절차
1. Toss Payments 가맹점/개발자 콘솔에서 테스트용 클라이언트 키와 시크릿 키를 발급합니다.
2. .env 파일에 아래 항목을 설정합니다.
   TOSS_CLIENT_KEY=발급받은 테스트 클라이언트 키
   TOSS_SECRET_KEY=발급받은 테스트 시크릿 키
   PUBLIC_BASE_URL=https://실제-테스트-도메인
   PRO_PRICE_KRW=3900
3. PUBLIC_BASE_URL은 HTTPS가 적용된 실제 서비스 주소여야 합니다. localhost 주소는 결제 활성화 조건을 만족하지 않습니다.
4. Toss 콘솔에 서비스 도메인/리디렉션 주소를 등록하고 테스트 카드로 승인 흐름을 확인합니다.
5. docker compose up -d --build 로 재배포합니다.

보안/결제 처리
- TOSS_SECRET_KEY는 서버 .env에만 저장합니다. 브라우저 코드나 저장소에 넣지 마세요.
- 결제 금액은 서버에서 만든 주문의 금액과 대조하며 브라우저가 보낸 금액만 믿지 않습니다.
- 결제 성공 리디렉션 이후 서버가 Toss 승인 API를 호출하고 응답을 검증한 뒤에만 PRO를 활성화합니다.
- 주문 ID는 사용자 계정에 귀속되며 다른 계정의 주문은 승인할 수 없습니다.
- 결제사 키가 비어 있거나 PUBLIC_BASE_URL이 HTTPS가 아니면 결제 버튼/승인 API는 비활성화됩니다.

아직 미구현 / 실제 판매 전 필수 작업
- 자동 정기결제(빌링키 발급·보관·갱신·해지)
- Toss 웹훅 수신/검증 및 결제 상태 대사
- 관리자 환불/부분취소 화면과 환불 후 이용기간 회수 정책
- 이메일 인증, 비밀번호 재설정
- 사업자/통신판매 관련 의무, 이용약관·환불정책·개인정보 처리방침 검토
- 운영 키 발급, 실제 도메인 배포, 보안 점검 및 결제사 심사

따라서 v10은 테스트 키로 결제 승인 플로우를 검증할 수 있는 통합 베타입니다. 운영 키를 넣었다고 즉시 상용 판매 준비가 끝나는 것은 아닙니다.
